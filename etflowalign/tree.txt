 PHASE 3 · 등변 벡터-피처 백본 (선행 구현)                            [x] 완료
================================================================================
- 목표: 회전 대칭을 지키는 "속도장 예측 신경망"을 밑바닥부터 구현
- 이유: 과거 병목 = 백본 표현력 부족 (스칼라-EGNN은 분자 모양 생성 불가)
- 게이트: 등변성 테스트 통과 (회전 1.11e-15, 이동 1.89e-15) [PASS]

[1] backbone/utils.py  — 공용 헬퍼
    - safe_norm()          : 거리 0에서도 유한 그래디언트 (NaN 방지)
    - soft_normalize()     : vec/(1+||vec||) 안정화 (SPEC §5.5)
    - scatter_add()        : torch_scatter 의존성 없는 native 집계
    - build_radius_graph() : 같은 분자 내 cutoff 이내 쌍 -> edge_index, r_ij, u_ij

[2] backbone/rbf.py  — 거리 특징화
    - CosineCutoff         : cutoff 반경에서 부드럽게 0으로 감쇠
    - ExpNormalSmearing    : expnorm 방사 기저 함수 (거리 -> num_rbf 채널)

[3] backbone/layers.py  — 등변 연산 블록
    - EquivariantAttention : 스칼라 h[N,F] + 벡터 vec[N,3,F] 동시 갱신
        · LayerNorm -> Q/K/V 투영
        · 어텐션 = SiLU(q·k ⊙ dk) * cutoff
        · 스칼라 메시지 s / 벡터 게이트 g1(피처) / g2(방향주입)
        · Δvec = 이웃벡터⊙g1 + 방향û_ij⊙g2
        · 출력투영 o1/o2/o3 -> dx = vec_dot*o2+o3, dvec = vec3*o1+집계
    - GatedEquivariantBlock: 벡터피처 -> out_channels 개 3D 벡터
        · zero_init 옵션으로 초기 출력 0 (안정화)

[4] backbone/embedding.py  — 입력 임베딩
    - SinusoidalTime       : 연속 시간 t in [0,1] -> sinusoidal
    - AtomTimeEmbedding    : 원자종 z -> h, 시간 t 를 분자별로 더함
    - (reference 조건 임베딩은 Phase 4에서 추가 예정)

[5] backbone/network.py  — 조립
    - EquivariantTransformer(F=256, layers=8, rbf=64, heads=8, cutoff=10)
        · forward(z, pos, t, batch) -> v_θ [N,3]
        · 임베딩 -> vec=0 초기화 -> 반경그래프 -> RBF/cutoff
        · N개 등변 어텐션 블록 (매 블록 후 soft_normalize)
        · out_norm(LayerNorm) -> velocity_head(zero-init) -> [N,3]

[6] tests/test_equivariance.py  — 게이트
    - 무작위 회전 R + 이동 τ 생성 (QR, det=+1)
    - v(Rx+τ) == R·v(x)  검사 (회전 등변)
    - v(x+τ)  == v(x)    검사 (이동 불변)
    - 출력 비자명성(out_mag>1e-3) 확인 -> zero-init 공허통과 방지
    - 실행: python -m etflowalign.tests.test_equivariance

 PHASE 2 · flow-matching 코어 (조건 없이)                             [x] 완료
================================================================================
- 목표: 백본 위에 생성 엔진을 얹어 "조건 없는" 3D 구조 생성부터 성립시킴
- 게이트 A: 소수 분자에서 정상 결합길이의 3D 구조 생성
- 결과: harmonic 20k + EMA + source정렬 -> aligned 0.694, bond 1.612/0.326 [PASS]
- ★핵심: 등변 백본은 source->target Kabsch 정렬 필수(없으면 생성 원리상 불가).
  train loss 내려가도 생성 정체(1.2)였다가, 정렬 추가로 0.69로 급락.
  (flow/path.py kabsch_align_source_to_target, FlowConfig.kabsch_source_align)
  + EMA(train.py class EMA) 추가. raw RMSD는 큰 게 정상(방향=등변성 처리).

[1] flow/prior.py  — 시작 분포(source)
    - HarmonicSampler : 결합 라플라시안 기반 (시작부터 결합거리 ~1.5Å)
    - GaussianSampler : fallback (게이트 A 이전 비교용)
    - x0 ~ prior(bonds)

[2] flow/path.py  — 보간 경로
    - linear path : x_t=(1-t)x0+t·x1, 목표속도 u=x1-x0
    - (옵션) Kabsch source->target 정렬  ※ pc@r vs pc@r.T transpose 버그 주의
    - 단위테스트: 정확 정렬쌍에서 정렬 잔차 ~0 확인

[3] flow/loss.py  — 목적함수
    - batchwise_l2 : 분자별 ||v_θ - u|| 평균 -> 배치 평균
    - 보조손실 없음 (bond/clash penalty 금지, SPEC §4.3)

[4] sampler.py  — ODE 적분 (생성)
    - Euler / few-step 적분, t: 0 -> 1
    - (포켓 UFF 가이던스 훅은 Phase 7에서 연결)

[5] train.py  — 학습 루프 (v0, 조건 없음)
    - 배치 로드 -> t 샘플 -> x0 샘플 -> x_t -> v_θ -> loss -> step
    - clip_grad_norm + nan_to_num (과거 NaN 크래시 방지)
    - best 즉시 저장 + NaN step 롤백

[6] scripts/03_smoke_generate.py  — 게이트 A 검증
    - 합성/소수 분자로 학습 -> 샘플 -> 결합길이/각 정상성 점검

 서버/GPU 운영 노트
================================================================================
- 타깃: 공용 GPU 서버, NVIDIA A10 x4 (각 23GB), CUDA 13.0, Driver 580.82.07
- 공용이므로 GPU 선택 필수: 사용 중인 카드 피하고 빈 카드 지정
    CUDA_VISIBLE_DEVICES=1 python ...   (0번은 종종 점유됨)
- 코드는 device-agnostic: model.to("cuda") + 배치를 GPU로 옮기면 그대로 동작
- A10 = Ampere -> tf32/bf16 지원. 대규모 학습 시 torch.set_float32_matmul_precision("high") 권장
- 서버 파일 범위 규칙: /gpfs/.../users/hosungkim 안에서만 생성/수정 (메모리 준수)

[성능 부채 — Phase 6(full 65k) 전 필수 벡터화]
  (a) flow/prior.py HarmonicSampler: 분자별 Python 루프 + .tolist() + eigh
      -> GPU<->CPU 동기화 폭발. 대안: eigen-decomp 사전계산 or 배치 eigh
  (b) flow/path.py center_pos / prior COM 루프: 분자별 for + .item()
      -> scatter_mean 기반 벡터화로 교체
  (c) backbone build_radius_graph: O(N^2) full pairwise. drug-sized/A10 OK,
      대형 배치에선 메모리 증가 -> 필요 시 radius_graph(torch_cluster) 교체
  * Phase 2~5(소규모/overfit)에서는 그대로 무방.
