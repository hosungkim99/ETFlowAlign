 PHASE 3 · 등변 벡터-피처 백본 (선행 구현)                            [x] 완료
================================================================================
- 목표: 회전 대칭을 지키는 "속도장 예측 신경망"을 밑바닥부터 구현
- 이유: 과거 병목 = 백본 표현력 부족 (스칼라-EGNN은 분자 모양 생성 불가)
- 게이트: 등변성 테스트 통과 (회전 1.11e-15, 이동 1.89e-15) [PASS]

[1] backbone/utils.py  — 공용 헬퍼
    - safe_norm()          : 거리 0에서도 유한 그래디언트 (NaN 방지)
    - soft_normalize()     : vec/(1+||vec||) 안정화 (SPEC §5.5)
    - scatter_add()        : torch_scatter 의존성 없는 native 집계
    - build_radius_graph() : 같은 분자 내 cutoff 이내 쌍 -> edge_index, r_ij, u_ij

[2] backbone/rbf.py  — 거리 특징화
    - CosineCutoff         : cutoff 반경에서 부드럽게 0으로 감쇠
    - ExpNormalSmearing    : expnorm 방사 기저 함수 (거리 -> num_rbf 채널)

[3] backbone/layers.py  — 등변 연산 블록
    - EquivariantAttention : 스칼라 h[N,F] + 벡터 vec[N,3,F] 동시 갱신
        · LayerNorm -> Q/K/V 투영
        · 어텐션 = SiLU(q·k ⊙ dk) * cutoff
        · 스칼라 메시지 s / 벡터 게이트 g1(피처) / g2(방향주입)
        · Δvec = 이웃벡터⊙g1 + 방향û_ij⊙g2
        · 출력투영 o1/o2/o3 -> dx = vec_dot*o2+o3, dvec = vec3*o1+집계
    - GatedEquivariantBlock: 벡터피처 -> out_channels 개 3D 벡터
        · zero_init 옵션으로 초기 출력 0 (안정화)

[4] backbone/embedding.py  — 입력 임베딩
    - SinusoidalTime       : 연속 시간 t in [0,1] -> sinusoidal
    - AtomTimeEmbedding    : 원자종 z -> h, 시간 t 를 분자별로 더함
    - (reference 조건 임베딩은 Phase 4에서 추가 예정)

[5] backbone/network.py  — 조립
    - EquivariantTransformer(F=256, layers=8, rbf=64, heads=8, cutoff=10)
        · forward(z, pos, t, batch) -> v_θ [N,3]
        · 임베딩 -> vec=0 초기화 -> 반경그래프 -> RBF/cutoff
        · N개 등변 어텐션 블록 (매 블록 후 soft_normalize)
        · out_norm(LayerNorm) -> velocity_head(zero-init) -> [N,3]

[6] tests/test_equivariance.py  — 게이트
    - 무작위 회전 R + 이동 τ 생성 (QR, det=+1)
    - v(Rx+τ) == R·v(x)  검사 (회전 등변)
    - v(x+τ)  == v(x)    검사 (이동 불변)
    - 출력 비자명성(out_mag>1e-3) 확인 -> zero-init 공허통과 방지
    - 실행: python -m etflowalign.tests.test_equivariance

 PHASE 5 · overfit-100 (capacity 게이트)                             [~] 진단중(막힘)
================================================================================
- 목표: 소수 정렬쌍을 "암기"시켜 모델 용량 확인 (일반화 전 필수 관문)
- 게이트 B: median aligned RMSD < 2Å
- 상태: 실분자 생성이 ~1.7~2.4Å에서 막힘. 원인을 한 겹씩 배제 중.

[진단 여정 — 배제된 원인들]
  · 회전:      force-align(오라클) → 3.365→2.263. 요인 맞으나 부족.
  · 개수:      n=4/20/100 전부 ~2.2~2.5 → 무관.
  · conditioning: unconditional → 2.056 → 조건부와 비슷 → 무관.
  · 용량:      HIDDEN=512/LAYERS=12 → 2.305 → 개선 없음 → 무관.
  · cutoff/크기: 크기 진단 작은2.35≈큰2.58 → 무관.
  · 측정(H):   GEOM 데이터 H=0(heavy=all-atom) → 지표 부풀림 아님.
  · 적분:      SAMPLE=500 → 2.393(100스텝 2.305와 동일) → 적분오차 아님.

[★핵심 통찰] "Gate A 통과=엔진 작동"은 착시였음.
  합성분자(랜덤트리+1.5Å결합) ≈ harmonic prior 분포 → transport trivial → 쉽게 통과.
  실분자(링·정해진 각도)는 prior와 완전히 달라 transport 어려움 → 못 그림.
  Acid test(단일 실분자 n=1): median 1.706. 분자 1개·간섭없음인데도 loss 요동(0.25~1.5)
  → 모델이 harmonic→실분자 속도장을 정밀표현 못함이 병목.

[남은 갈림길 — 미판정]
  (a) 학습 분산:  B1(스텝당 다중 x0·t로 분산↓)으로 분자1개 loss가 ~0 가나?
  (b) 모델 표현력: 안 가면 formulation(C1 GVP path / C2 prior) 또는 백본 재설계.
  → 다음 실험: N=1 UNCOND MICRO=8 sbatch run_overfit.sh

      대형 배치에선 메모리 증가 -> 필요 시 radius_graph(torch_cluster) 교체
